# RemoteScreen 桌面端

**一个应用、一个窗口**，深色侧栏 + 浅色主区，界面参照 ToDesk：

```
┌──────────┬────────────────────────────────────────────┐
│   头像    │                                            │
│  立即登录 │  允许远程观看本设备             [开关]      │
│          │  设备代码            连接密码               │
│ 远程投送  │  820 302 612         tgmyet   显示  换一个  │
│ 我的设备  │  观看 0 人                    未投送        │
│ 投送设置  │                                            │
│          │  连接其他设备                  ✓ 已准备好    │
│          │  [ 请输入对方设备代码 ]  [    连接    ]      │
│          │  [ 连接密码（连自己的设备可留空） ]          │
│  Remote  │                                            │
│  Screen  │                                            │
└──────────┴────────────────────────────────────────────┘
```

左侧三个页面：

| 页面 | 内容 |
| --- | --- |
| **远程投送** | 设备代码与连接密码、投送开关、连接其他设备 |
| **我的设备** | 账号下的全部设备，含在线状态与一键连接 |
| **投送设置** | 采集源选择、分辨率 / 帧率 / 画质 / 编码、声音开关、服务器地址 |

**投送用一个开关而不是按钮** —— 这是从 ToDesk 学来的：开关比按钮更直白地表达「这台设备现在可以被看到」。
采集源不用每次选，默认跟随主屏，要改去「投送设置」（投送过程中不能改）。

## 账号

右上角可以登录 / 注册。**设备绑定到账号**：

- 登录后左栏才出现本机信息与投送设置 —— 一台设备必须归属于某个账号
- 右栏顶部会出现「我的设备」，列出你名下所有设备及在线状态，点「连接」即可**免密码**连自己的设备
- 换台电脑登录同一账号，看到的是同一份设备列表

**对外分享仍然走「设备 ID + 连接密码」**：别人不需要注册，把 ID 和密码给他就能看。
两条路径并存，服务端的响应里用 `via` 字段标明这次是靠账号（`owner`）还是靠密码（`password`）授权的。

账号存在服务端的 SQLite 里，会话有效期 30 天，退出登录会立即吊销令牌。

## 运行

```bash
npm install
npm run vendor         # 把 LiveKit 的 UMD 构建复制进渲染层
npm run start:remote   # 连生产服务器
```

不带 `:remote` 的 `npm start` 走本机 `127.0.0.1:8787`，用于本地开发。右侧「服务器设置」也能随时改地址，改完会记住。

## 配合使用

1. **A 电脑**运行本应用，左栏显示设备 ID 与连接密码
2. **B 电脑**在同一应用的右栏输入那两项 → 点连接
3. 回到 A 点「开始投送」，B 那里就出画面了

手机 / 平板可以打开 `http://91.208.104.182/viewer/`——同一份页面，检测到是浏览器加载时会自动只显示右栏。

## 采集设置

四项可选，**改动在下次「开始投送」时生效**（投送中会被禁用，避免误解）：

| 项 | 选项 | 说明 |
| --- | --- | --- |
| 分辨率 | 跟随原始尺寸 / 2560×1440 / 1920×1080 / 1280×720 | 屏幕采集默认给的是**原生像素尺寸**，Retina 与 5K 屏上可达 5000+ 宽，直接推会同时压垮编码器与上行带宽 |
| 帧率 | 15 / 30 / 60 | 屏幕内容大多静态，30 通常足够；60 会成倍增加编码与带宽开销 |
| 画质 | 流畅 1.5 / 均衡 3 / 高清 6 Mbps | 码率上限 |
| 编码格式 | H.264 / VP8 / VP9 | **默认 H.264**：macOS 走 VideoToolbox 硬件编码，手机端硬件解码 |

默认组合：**1920×1080 / 30fps / 均衡 / H.264**。

### 遇到卡顿怎么定位

画面上的覆盖层实时显示 `分辨率 · 帧率 · 码率`，按这个顺序看：

1. **帧率低但画面内容没在变** → 正常。屏幕采集是**内容驱动**的，画面不变就不产生新帧
2. **画面在动但帧率上不去** → 看投送自检里的「编码器受限原因」：`cpu` 就降分辨率，`bandwidth` 就降码率或帧率
3. **码率远低于上限却仍然卡** → 上行或国际链路拥塞，先降到 1280×720
4. **三项都正常还是卡** → 大概率是观看端解码吃力，同样降分辨率

## 自检

```bash
# 投送能力
npm run selftest -- --hold=20 --resolution=1920x1080 --framerate=30 --codec=h264

# 观看能力
npm run selftest:viewer -- --device=<设备ID> --password=<密码> --server=http://91.208.104.182
```

投送自检在保持推流期间采样发送侧指标（实际编码器、编码与实发帧数、码率、RTT、NACK、编码器受限原因）。
观看自检统计**真正被解码渲染出来的帧数**，并附带诊断字段（`readyState` / `hasSrcObject` / 订阅事件），
便于区分「轨道没到」与「到了但没渲染」。

## 打包

```bash
npm run package:win     # Windows x64 → dist/RemoteScreen-win32-x64.zip
npm run package:mac     # Apple Silicon Mac → dist/RemoteScreen-darwin-arm64.zip
```

产物是**免安装版**：解压后直接运行，不需要安装。

| 说明 | |
| --- | --- |
| **为什么不用安装程序** | 打 Windows 安装程序（NSIS）需要 Wine；免安装版只是把 Electron 运行时与源码复制到一起，任何平台都能构建 |
| **体积** | zip 约 158 MB，其中 99% 是 Electron 运行时；**应用代码本身只有 658 KB**（`app.asar`） |
| **没有代码签名** | Windows 首次运行会被 SmartScreen 拦（"Windows 已保护你的电脑"）→ 点「更多信息」→「仍要运行」。macOS 首次打开需右键 →「打开」。要消除提示需要购买 Windows 代码签名证书和 Apple Developer 账号 |
| **不依赖 node_modules** | 主进程只用 Electron 与 Node 内置模块，渲染层的 LiveKit 来自 `vendor/` 下已构建的 UMD。所以打包时可以整个排除 `node_modules`，不显式排除的话打包工具会把自身的传递依赖塞进去 |

## 手机上怎么用

**Electron 不支持手机**（只能跑 Windows / macOS / Linux），所以手机走网页版：

1. 手机浏览器打开 `http://91.208.104.182/viewer/`
2. 输入设备 ID 与连接密码

**建议添加到主屏幕**，这样点开就是全屏应用，没有地址栏：

| 系统 | 操作 |
| --- | --- |
| iPhone / iPad | Safari 底部分享按钮 → 「添加到主屏幕」 |
| Android | Chrome 右上角菜单 → 「添加到主屏幕」/「安装应用」 |

图标与应用名已经配好了（PWA 清单 + 多尺寸图标），加完之后桌面上是一个正常的应用图标。

图标由 `scripts/make-icons.py` 生成 —— 环境里没有 Pillow，所以脚本直接按 PNG 规范写字节，
并用 4 倍超采样保证圆角平滑。

## ⚠️ 三个环境坑

**一、`ELECTRON_RUN_AS_NODE=1`**

环境里若存在这个变量，Electron 会退化成纯 Node 运行，报
`TypeError: Cannot read properties of undefined (reading 'setName')`，堆栈里会出现 Node 版本号。
`npm run selftest` 已用 `env -u` 规避，手动运行时需自行 unset。

**二、受限 shell 下需要 `--no-sandbox`**

沙箱化终端里 Chromium 自身的沙箱无法初始化，报 `sandbox initialization failed: Operation not permitted`。

**三、`npm install` 可能不执行 electron 的 postinstall**

表现为运行时 `node_modules/electron/dist` 不存在。补下载：

```bash
node node_modules/electron/install.js
```

## 平台差异

| 能力 | Windows | macOS |
| --- | --- | --- |
| 屏幕画面 | ✅ | ✅ |
| 系统音频 | ✅ `audio: 'loopback'`（WASAPI 回环） | ⛔ Chromium 不支持，需改用原生 ScreenCaptureKit |

macOS 上拿不到系统音频是 Chromium 的限制，不是配置问题。因此本应用**不能**作为 macOS 的最终采集方案，
macOS 最终要用 Swift + ScreenCaptureKit 重写。

## 为什么一份代码能同时当桌面应用和网页

渲染层只用标准 Web API，不依赖任何 Electron 能力，因此 `src/renderer/` 是自包含的静态目录，
可以被 Electron 加载，也可以原样托管给浏览器。页面检测到自己是通过 `http(s)` 加载时会自动隐藏左栏，
只保留「连接」——手机没有可投送的桌面，露出来只会造成困惑。

代价是渲染层不能用 Node 能力，但观看端本来也不需要。

## 目录结构

```
src/
├── main/
│   ├── index.js          主进程：窗口、采集源枚举、屏幕捕获授权、凭据与心跳
│   ├── device-client.js  设备目录服务客户端（注册 / 心跳 / 刷新密码 / 下线）
│   └── device-store.js   本地凭据持久化（0600 权限）
├── preload/index.js      contextBridge 暴露的最小接口集
└── renderer/
    ├── index.html        单页两栏
    ├── app.js            投送 + 观看两套逻辑
    ├── styles.css
    └── vendor/           LiveKit UMD（构建产物，由 npm run vendor 生成）
```

**职责边界**：凭据读写与设备目录服务调用全在主进程；渲染进程只拿到连 LiveKit 所需的那一枚令牌。
