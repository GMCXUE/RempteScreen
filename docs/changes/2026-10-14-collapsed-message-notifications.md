# 折叠状态的多条消息通知

此前 MessagingStyle 将同一好友多条消息写到同一个系统通知记录，折叠后只显示最后一条；发送人还可能被系统放到通知卡片标题位置。新实现将每条新消息作为独立子通知，所有聊天子通知按本账号分组，并为两条以上消息创建系统分组摘要。同一好友连发四条时也有四个子通知，供系统在未展开状态展示多行及剩余数量标记。应用不绘制或伪造系统的“+N”、透明卡片或锁屏主题；具体行数和外观由 SystemUI 决定。

Android 使用普通 BigTextStyle 子通知，头部应用名称来自 RemoteScreen 的应用标签，发送人与内容在消息正文部分。子通知使用账号、好友与消息序列构成的独立 tag，不再覆盖同一好友的上一条；通知点击和清除的 PendingIntent 也分别标识每条消息。单独划掉一条仅移除该条，查看对应聊天才批量清除该好友的通知；清除整个分组移除本账号剩余聊天通知。新消息只从上次成功提交的序列之后生成，批量中部分提交失败时保留成功游标，避免重放旧提醒。同一批消息只让最后一条发出声音。

每个好友最多保留五条，整个账号最多二十条，按消息序列排序。通知内容开关、其他设备已读后的本机通知保留、账号切换清理仍生效。升级时清理旧版单一会话卡片。后台服务的两条常驻待命通知属于前台服务，未混入聊天通知分组。

macOS 同步改成每条消息独立的系统通知标识和账号级线程分组，按相同上限保留并按好友批量清理；Windows 提交独立标识，但现有 Tauri 通知后端不支持撤销已展示记录，系统分组与外观由 Windows 控制。本次仅发布 macOS 和 Android 完整安装包。服务器继续使用现有的五条通知摘要字段，无需部署或数据迁移。

验证：Robolectric Android 35 框架模拟检查五项全部通过，覆盖同一好友四个子通知与一个分组摘要、单条划除与会话查看、内容隐藏、五条/二十条上限、相同 Java hash 的好友标识隔离；原安卓通知策略九项通过。Rust 通知策略六项及 macOS 原生构建通过，移动端点击路由静态检查无问题。测试库仅作为 testImplementation 依赖，不进入发布 APK。修复 Gradle 9 主机测试包装任务对 Flutter 资源复制任务的缺失依赖。

没有在线或可发现的 Android 调试设备，尚未验证截图中 HyperOS 的实际折叠渲染；框架模拟确认系统收到多条独立子通知，不能代替手机 SystemUI 外观测试。

发行：macOS 0.2.15、Android 0.2.21，构建号 2026101402。参考：[Android 通知分组规范](https://developer.android.com/develop/ui/views/notifications/group)。
