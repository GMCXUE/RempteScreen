# 投屏方显示观看方摄像头

此前摄像头只显示在主应用的投屏页面，投屏方离开应用后不可见。安卓开启 adaptiveStream 时，原先的裸 RTCVideoView 也没有向 LiveKit 上报摄像头渲染可见性，可能导致服务端暂停该订阅。

- 桌面端：收到摄像头首帧后自动打开独立置顶窗口，默认位于右上角，可拖动、调整大小。投屏页面的“视频悬浮窗”可以重新打开。关闭摄像头或结束投屏后自动清理窗口。
- 安卓：投屏页面提供同名按钮，首次使用打开系统“显示在其他应用上层”授权页。授权后，接收的摄像头通过现有 WebRTC 轨道的原生 sink 渲染到可拖动的小窗，切换应用后保留。拒绝授权时仍可在应用内看视频。小窗使用 FLAG_SECURE，避免重复采集通话视频；部分系统录屏会在该区域显示黑色遮挡。
- Flutter 内部摄像头显示改用 LiveKit VideoTrackRenderer，正确上报可见性。投屏方关闭 adaptiveStream，以免 Flutter 页面进入后台后暂停原生悬浮窗使用的订阅；屏幕发布编码设置保持不变。

小窗复用已订阅的视频，不重新发布、不混入屏幕视频轨。Android 需要用户手动授权系统悬浮窗权限；桌面端无此授权要求。使用平台录屏保护，具体对屏幕共享的排除效果需实机确认，macOS 版本可能限制窗口保护能力。

已通过双端 release 编译、JavaScript 语法检查、git diff --check。Flutter 静态分析只有已有的 AudioSessionOptions experimental_member_use 警告。摄像头实机画面、跨应用显示及系统录屏保护效果尚未进行通话测试。

已覆盖安装 `/Applications/RemoteScreen.app`，签名校验通过并启动。安卓通过已配对的无线调试覆盖安装成功，安装更新时间为 2026-10-10 18:50:40，未替用户开启系统悬浮窗授权。

后续样式调整：两端统一深色圆角、细边框和底部 34px 状态条，摄像头按原始比例显示。桌面去掉系统标题栏，画面与状态条均可拖动；安卓使用圆角视频区域和柔和阴影。按用户要求，两端均不提供关闭按钮，随摄像头关闭或会话结束自动收起。
