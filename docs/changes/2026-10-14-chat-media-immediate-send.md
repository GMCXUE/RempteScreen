# 视频运行依赖与移动端媒体确认直发

线上最近七次视频上传均返回 400。只读诊断确认运行中的 device-service 镜像没有 FFmpeg 或 FFprobe；虽然生产 Dockerfile 已含安装指令，旧运行镜像未包含对应依赖。原探测函数将程序缺失误报为视频格式错误，导致正常视频也无法发送。

服务器新增镜像构建时的视频依赖检查，验证 FFmpeg、FFprobe 及 H.264/AAC/JPEG 编码器；缺少或不能执行媒体程序时返回 503“视频服务暂不可用，请稍后重试”，不再误导用户重新选择 MP4。视频接口错误日志仅记录处理器返回的错误原因，不输出文件内容、令牌或 FFmpeg 原始日志。格式错误、五分钟及 50 MB 限制保持原有行为。

移动端相册选择图片/视频或拍照确认后，整批直接进入现有发送队列，取消待发送缩略图栏和第二次发送确认。文字草稿独立保留，不会随媒体选择一起发送；取消、选择失败、超过九项以及离开聊天后的迟到结果均不产生部分消息。失败项目保留原编号供重试，成功的项目不重发。

移动端与主桌面客户端都在失败消息下直接展示实际原因，并保留重试按钮。待上传视频在移动端使用深色占位块，避免白色播放图标落在浅色背景上。按用户明确限定，自动发送仅作用于移动端；桌面图库和粘贴图片继续保留待发送确认。此平台交互差异不改变共享协议、文件上限、队列和错误文案。

验证：移动端十四项真实页面/上传/播放/重试回归通过，静态分析无问题；桌面实际页面回归与 Rust 编译检查通过。服务器缺失运行依赖四项回归通过；隔离 PostgreSQL 测试数据库配合真实 FFmpeg 8.1.2 验证上传、H.264/AAC 转码、去除元数据、缩略图、同编号幂等重试、完整下载与哈希、Range/HEAD、权限、历史、撤回和清除全部通过。测试只使用合成文件与隔离账号，没有发送用户消息。

本次仅发布 macOS 0.2.16、Android 0.2.24，构建号 2026101405 的完整安装包，不发布热更新。生产服务只重建 device-service，保留数据库、LiveKit、Caddy、更新密钥和安装包挂载；旧镜像与源码保留用于回滚。没有在线 Android 调试设备，手机上的真实图库交互仍待确认。

用户讨论后确认沿用微信方向：普通聊天由服务器投递并有限暂存，客户端完整下载、校验和可靠落盘后长期保留，换设备通过已有加密备份与迁移机制恢复。继续采用已选的七天期限及旧记录迁移保护；聊天视频仍在服务器转码和生成缩略图，此方案不是端到端加密。设备文件传输继续仅在服务器长期保存发送记录，不保存文件内容；其 LiveKit 数据通道仍可能经过中转服务器。
