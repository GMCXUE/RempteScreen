# 聊天通知策略检查与优化

本次修改 Flutter Android 与 Rust 桌面客户端。保留现有头像、发送时间、单条折叠消息、每会话五条及全应用二十条聊天通知展示；不改变原有普通后台接收范围，不新增厂商推送、FCM 或 APNs。

## 已修复

- 前台其他页面收到聊天消息时只显示应用内横幅，避免同一条消息同时弹出系统横幅。当前打开的会话继续抑制额外提醒。
- 后台聊天与好友申请共用本设备账号级十秒声音限频。超过一分钟的积压消息只展示、不补响；消息仍正常同步，来电不受此限频影响。
- 双端新增“聊天消息通知”和“好友申请通知”开关，默认开启、按本设备账号保存；关闭通知不会停止接收消息或修改服务器未读。关闭期间经过同步的消息不在重新开启后重放。
- 好友申请遵循“通知显示消息内容”；关闭预览立即清理旧的含身份通知。Android 通知点击使用含账号与事件的 URI，避免整数哈希碰撞导致跳错目标。
- Android 在头像请求结束后重新核对账号、前台会话及最新设置，通知提交与设置修改/账号切换串行化。来电头像加载后也重新检查声音与免打扰设置。
- Android 点击通知不再提前清空整段会话通知；进入会话时才执行本机清理。划掉通知仍不等于服务器已读；清除旧汇总时仅处理该汇总的序列范围，不误删随后到达的新消息。
- 双端阅读历史时不再将尚未查看的新消息标记已读；回到最新消息区域后恢复已读同步。当前会话的通知抑制与服务器已读分别处理。
- Android/macOS 在下一轮同步中移除已撤回、已清空、删除好友或拉黑后不再有效的通知。其他设备已读不会直接清除本设备仍保留的提醒。
- macOS 只有系统允许且确认接受通知提交后才推进通知游标；失败自动重试。桌面好友申请去重记录落盘，重启不会把同一申请再次提醒。设置与系统提交通道串行化，隐藏内容设置在提交前再次生效。
- Android 诊断读取实际使用的声音/静音频道，避免选择静音后仍报告另一个频道的状态。

## 范围与平台差异

- 后台服务仍按四秒间隔轮询，实际延迟还受网络请求、系统调度与电池策略影响；不能保证进程被清理、强制停止或系统冻结期间到达。恢复后补同步，推送仍为后续独立接入工作。
- Windows 沿用现有 Tauri 通知后端，暂不能可靠撤销已经显示的系统通知。已应用共同的设置、前台去重、限频、已读及请求去重规则；本机未验证 Windows 系统通知。
- 通知快捷回复、系统“标记已读”操作及应用内定时免打扰尚未实现；当前通过点击进入聊天回复，勿扰时段由系统控制。
- 系统锁屏外观、声音、振动、专注模式，以及真实手机后台到达率仍需真机验收。自动化通过不代表已验证到达率。
- 本次通知优化与已发布的视频发送修复及移动端媒体确认直发整合；合并后的 macOS 0.2.17、Android 0.2.25（构建号 2026101406）采用完整安装包。
