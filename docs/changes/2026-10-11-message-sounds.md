# 消息提示音与来电铃声

本阶段同步修改 primary Rust Mac 客户端和 Flutter Android 客户端，不修改已部署的服务端协议。

消息提示按最新收到的消息序号去重：正在查看该会话时不额外提示；前台其他页面使用可点击的轻提示和一次消息声音；后台使用系统通知及通知声音。通话结束记录保留未读，但不会额外弹出消息提醒或响一次消息音。好友申请遵循消息声音开关。

语音、视频来电持续响铃；打开来电通知查看界面不会自行静音。接听、拒绝、取消、其他设备接听或服务端结束后停止。用户主动接听/拒绝立即停止本地铃声；远端变化随约 4 秒通知状态轮询撤下。铃声独立于通知 UI，按服务端创建时间加 45 秒截止，即使请求失败也不会无限响铃；同一来电被用户处理后旧状态不会重启铃声。

Mac 使用系统 Glass 消息音、Purr 循环来电音，由原生线程播放与终止，避免网页自动播放限制。安卓使用默认通知音和默认来电铃声，来电配合循环振动；遵循通知权限、静音/振动模式和系统勿扰。声音使用通知/铃声用途，不改通话或投屏音频配置；来电通知采用无声音通道，避免通知和独立铃声重复播放。安卓 SDK 28 起使用 Ringtone 循环，低版本通过原生定时器继续播放。参考：[Android Ringtone](https://developer.android.com/reference/android/media/Ringtone)。

双端消息页增加“消息与来电提醒”，提供消息声音和来电声音开关；安卓来电开关联动振动。好友菜单提供开启/关闭免打扰：消息仍保留红点，不弹新消息提示；来电仍显示可接听界面与通知，但不响铃或振动。设置按账号保存在本设备，退出重登仍保留，不跨设备同步。Mac 保存在应用数据目录，安卓保存在应用私有首选项中。原有安卓后台服务与 Mac 需保持进程运行的限制不变，未接入杀进程后的厂商离线推送或 iOS APNs。
