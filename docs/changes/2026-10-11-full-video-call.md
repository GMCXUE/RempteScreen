# 独立视频通话窗口与双方画面

- 桌面好友视频通话接通后进入独立窗口，默认最大 960×720，按屏幕尺寸收缩，最小 520×380。视频铺满窗口，支持全屏和 Escape 退出全屏。收起后使用视频小窗返回通话。
- 移动端视频通话使用整个页面显示画面，顶部资料和底部操作浮在视频上。支持横竖屏布局；控制栏可手动隐藏，空闲 4 秒自动隐藏，轻点画面或“显示控制栏”恢复。等待接听和通话连接过程中不自动隐藏操作。
- 双端默认对方占主画面，自己显示在右上角小窗。点击小窗可交换双方大小，隐藏控制栏后仍可交换。摄像头未开启时使用头像和状态占位，不保留上一帧。
- 接通后的操作分两行：麦克风、摄像头、声音在上方；红色挂断按钮在下方居中，圆形尺寸稍大。小窗口和横屏仍保留此布局。
- 正常挂断后只保留聊天里的通话记录，不再常驻“通话已结束”。拒接、未接听、离线及连接失败仍提供 2.2 秒临时提示；桌面通话提示不再写入聊天错误栏，聊天加载等真实错误仍可显示。
- 桌面自己的画面从现有摄像头视频轨生成预览，macOS 和 Windows 均使用相同预览路径，不启动第二个采集器。Flutter 使用同一房间的本地及远端摄像头轨。两端自己的自拍预览跟随动作方向，前置预览在显示层水平翻转；后置和对方画面保留正常方向。该翻转不改变采集、发布或对方收到的画面，大小窗切换后保持同一预览规则。
- 主窗口继续负责信令与媒体会话。独立窗口只显示画面、转发控制并维持本地媒体心跳。收起后点击视频小窗返回，不重复连接或重新发布摄像头；结束通话直接关闭完整窗口和小窗并清空预览。
- 窗口创建在后台线程执行，设置 12 秒超时。过时的窗口更新被跳过；挂断直接清理窗口状态，迟到的创建结果不会持续显示已结束的通话。失败时主窗口保留控制入口。
- 平台差异：桌面以独立系统窗口承载视频，移动端以应用内完整页面承载视频。两端采用相同的主画面/小窗切换、控制栏隐藏和媒体操作。

- 覆盖检查中复现了 Mac 摄像头 NV12 帧进入本地预览时触发 SDK 原生回调崩溃。Mac 采集现在先转换成 I420，再交给同一视频轨，预览与发布都使用兼容格式；帧长度不完整时直接返回错误。Windows 采集原本使用 I420，安卓由 SDK 管理采集，不需要这项平台修复。
- 两端应用内来电卡片改为头像、名称/来电类型、接通/挂断图标的一行布局，长名称省略显示。Mac 系统浮窗继续保留头像和右下角小图标。
- 移动端 SDK 的本地视频点击对焦手势曾抢占小窗点击。通话舞台现在统一处理视频触摸，渲染器只显示画面；小窗全区域可切换，自己的画面切到主画面后也能点击隐藏/恢复控制栏。
- 视频通话收起后取消重复的“返回通话”条，返回入口整合到视频小窗。桌面原生小窗为 180×240，安卓原生及应用内备用小窗为 120×160；摄像头关闭时保留通话占位入口。语音通话保留原返回条，不创建视频小窗。
- 小窗正常点击返回完整通话；拖到左右边缘并松手后收成 28×64 的箭头标识，点击标识只展开小窗，再点小窗返回。桌面按当前显示器处理位置，移动端限制小窗在屏幕内，挂断自动清理，不再点击缩成圆圈。
- 安卓收起按钮和系统返回键都会检查悬浮窗权限。缺少权限时显示“开启悬浮窗 / 取消 / 去授权”引导，“去授权”打开本应用的系统悬浮窗设置；取消或未授权时保留完整通话页。授权后再次收起即可显示系统小窗。其他移动平台以应用内小窗作为备用入口，桌面使用原生窗口，无需安卓权限。
- 安卓原生小窗通过当前通话 ID 和账号 ID 打开完整通话，原生事件即时通知 Flutter 路由；普通后台继续复用现有媒体会话。本次未扩展进程被系统清理后的推送能力。

验证：Flutter 通话状态、来电卡片、视频页面、授权引导及小窗检查共 15 项，覆盖 SDK 对焦/缩放手势、横竖屏、取消授权与返回键、左右贴边及点击恢复。预览方向检查使用真实 SDK 的前置、后置和远端渲染器，确认只有自己的前置预览水平翻转、交换不重新采集且不修改视频轨；三项视频预览合成帧检查覆盖实际 Mac NV12 采集路径的预览像素与帧长度校验，以及关闭/静音后迟到帧不能恢复画面。桌面浏览器回归检查验证双路帧源、自拍及远端显示方向、铺满窗口、交换、隐藏/恢复、全屏、操作路由、小窗返回及贴边、过期操作忽略和结束清理，以及正常结束不重复提示、异常提示不占聊天错误栏。另有 Rust 多显示器位置检查一项、安卓原生位置检查两项，以及相关 Dart 静态分析与原生编译。
