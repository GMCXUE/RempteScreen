# 通话采集修复

桌面摄像头的 `NativeVideoSource.capture_frame` 返回 false 代表适配器正常丢帧，旧实现误判为失败并停止采集。现在继续读取后续帧，首次摄像头帧最多等待 60 秒。

桌面麦克风改为 cpal 独立输入和 NativeAudioSource，避免 PlatformAudio 启用全局 ADM、语音处理及播放改变现有投屏声音路径。macOS 摄像头和麦克风先显式请求 AVFoundation 权限。按钮操作期间禁用重复点击并持续展示处理状态；失败提示不会被轮询刷新覆盖。

安卓原生补丁原本只给 WebRTC 全局输入提供系统声音。投屏期间再发布 microphone 轨会共用这个输入，并重新启用语音处理。现在投屏端使用独立 AudioRecord 采集显式开启的麦克风并限幅混入系统 PCM，不重新发布音频轨或切换全局处理。关闭麦克风、结束投屏时释放该采集器。观看端恢复普通麦克风输入，解决投屏结束后仍使用静音替代输入的问题。

平台差异：安卓投屏端的麦克风和系统声音通过同一投屏声音轨发送，接收端无法独立调节两者；投屏控制卡片已提示这一点。安卓同时投屏并观看时不能再用第二个会话独立采集麦克风。桌面及安卓纯观看会话仍使用独立通话轨。

编译与静态检查不代表真实设备声音、摄像头和权限流程已经验证。

修复后的 Mac 应用和安卓 release 包已覆盖安装并启动；Mac 使用临时签名。
