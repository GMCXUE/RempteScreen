# HyperOS 原生聊天通知与名称旁时间

在用户授权连接的 Xiaomi 25019PNF3C（Android 17 / SDK 37，HyperOS OS4.0）上排查 Android 0.2.26：消息后台前台服务运行、通知权限允许、聊天频道为 HIGH，NotificationManager 已接收聊天通知，但 SystemUI 将通知放进“更多通知”。应用及频道的悬浮、锁屏开关均已开启，因此不能把本次现象解释成没有收到服务器消息或没有通知权限。

真机截图显示自定义 RemoteViews 中的发送人头像与 Builder.largeIcon 被同时绘制，造成重复头像及正文拥挤。同一临时离线测试应用对照：原生子通知正常合并为多行及 +N，自定义子通知进入更多通知。随后按用户要求直接检查抖音的现有通知：其普通原生通知没有自定义布局；收起显示应用图标与多条私信摘要，展开后每条显示头像、名称及私信正文。仅检查样式字段，不记录用户私信内容；手机截图和临时工具不提交到仓库。

聊天子通知改用原生布局，保留账号、好友、消息序列、点击路由、头像缓存、隐藏预览、五条/好友及二十条/账号上限、单条删除和查看会话清除策略。Xiaomi 使用普通原生通知，匹配该真机的名称头部及长文展开；其他 Android 使用原生 BigTextStyle 支持长文展开。分组摘要补充 MESSAGE 类别。删除两个自定义布局，不再重复绘制头像。

用户最终要求：删除每条右下角额外时间，并保留抖音式名称旁系统时间。子通知、摘要及匿名锁屏版本使用真实发送时间的 when/showWhen，由 SystemUI 显示“现在/几分钟前”等系统格式；消息正文不拼接时间。应用内手机卡片将发送时间移到名称旁，取消回复按钮下面的时间栏。桌面现有卡片已在名称旁显示发送时间，原生系统通知亦保留系统时间，因此桌面行为无需新增实现。本次是 Android 的 SystemUI 兼容修复，仅发布 Android 0.2.27 / 2026101408 完整 APK。

系统仍拥有通知过滤、分组、相对时间与最终样式的控制权，本次不修改用户的通知频道设置或全局过滤设置，不通过未公开厂商接口强制绕过。原生布局对照成功不能代替正式包的账号通知投递验证，发布前继续在同一手机验证真实后台/锁屏聊天和已读清除。

验证：Android 原生通知与投递回归 32 项通过，包含 Xiaomi 普通模板、其他 Android BigTextStyle、头像、真实头部时间、匿名版本、分组、单条删除、已读清理及前后台横幅确认。Flutter 卡片/聊天视口 11 项通过；桌面消息卡片原有布局保留。真机对照确认多行收起、+N、逐条头像和普通通知长文展开。

参考：[Android 自定义通知限制](https://developer.android.com/develop/ui/views/notifications/custom-notification)、[小米通知过滤说明](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1577)。小米文档的旧版“设为重要”轻滑入口在本机不存在，不能将旧入口当作本机已验证操作。
