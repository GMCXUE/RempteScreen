# 好友语音、视频通话（第二阶段）

双端聊天页新增语音/视频呼叫入口，支持来电提示、接听、拒绝、取消、挂断，以及麦克风、摄像头和接收声音开关。通话由全局管理器持有，切换聊天或其他页面继续通话。桌面通话面板放在右上方，不遮挡输入区；移动端支持展开通话画面，并复用安卓视频悬浮窗与麦克风/摄像头前台服务。

## 与投屏隔离

好友通话使用 friend-call-UUID 独立 LiveKit 房间，双方身份固定为该呼叫 caller/callee。通话令牌仅允许 microphone（语音）或 microphone/camera（视频），不允许屏幕轨与数据发送。挂断聊天不会断开投屏或文件会话。

投屏端与观看端移除摄像头操作入口，保留投屏语音与系统声音。聊天开始时暂停本机已打开的投屏麦克风，通话结束后恢复；聊天期间尝试开启投屏麦克风会提示先结束好友通话。安卓已有投屏语音仍按原方式混入投屏声音；新的好友通话另建 PeerConnectionFactory 与 JavaAudioDeviceModule，隔离投屏 PCM 和通话麦克风，避免共用输入导致麦克风无法打开或系统声音被替换。房间与麦克风约束均显式选择独立实例，ICE/TURN 配置 copyWith 及重连继续保留该选择。

桌面复用现有原生麦克风/摄像头采集，增加麦克风操作串行锁，暂停与恢复原投屏轨；视频帧按通话实例隔离，旧会话清理不能覆盖新会话画面。媒体采集在接听后才启动。权限申请期间挂断，晚到的采集结果检测已关闭状态并释放；主界面停止同步超过 35 秒时原生采集也会停止。

## 服务端信令

新增持久化 friend_calls 表。POST /v1/social 下四个操作均使用账号 Bearer：

- call-start：clientId、peerId、kind（voice/video）。同一客户端重试同一正在进行的呼叫返回原呼叫。
- call-state：clientId、可选 skipCallIds（本机已停止且待重试挂断的呼叫，不再续租）。返回账号呼叫状态，仅被选中的呼叫或接听客户端获得媒体 grant。
- call-decision：clientId、callId、accept。被叫账号的多台设备均可看到来电，只允许一台抢答；其他设备收起提示，不能获取媒体令牌。
- call-end：clientId、callId。仅发起或接听的设备可挂断，结束操作幂等。

事务级 advisory lock 保证交叉呼叫与多端抢答原子化，每个账号同时只有一个待接听/进行中呼叫。发起需好友且双方未拉黑；好友关系变化会结束通话。响铃 45 秒未接听自动结束，选中客户端 35 秒不续租视为离线；每次信令操作清理过期呼叫。客户端约每 2 秒同步，网络持续异常约 30 秒关闭本地通话。掉线、拒绝、取消、未接听、好友变化都有对应提示。

本地挂断先清理媒体，再请求服务；信令失败保留挂断重试并停止续租，避免网络恢复后重新打开已挂断的呼叫。账号切换丢弃迟到响应。通话结束结果现已同步写入聊天记录（见下方补充）。

## 通话视频显示修复

桌面通话帧改为 Image 直接加载 friendcamera 自定义协议，沿用投屏摄像头已使用的显示路径，避免跨协议 fetch 被 WKWebView 的跨域检查拦截后静默隐藏画面。保留单个在途请求、3 秒加载超时和通话实例检查，挂断后的迟到帧不能重新显示。隔离浏览器模拟帧检查通过：禁用 fetch 后视频仍显示，挂断后隐藏；此检查不等于真实设备的视频订阅验证。

安卓原生浮窗移除 FLAG_SECURE：该标记会让 MediaProjection 把浮窗区域替换成黑块。视频改为 TextureView + EglRenderer，避免 SurfaceView 的独立合成表面造成裁剪/遮挡问题；纹理销毁时等待 EGL 表面释放，关闭时移除 sink 并释放 renderer，保留拖动、收起和圆角。小窗口现在会出现在投屏画面中，不再刻意屏蔽该区域。原生 Kotlin 编译及 Android release 构建通过，实际黑块是否消除仍需真机复验。

视频显示修复版已覆盖安装安卓与 Mac 测试签名应用并启动，服务端无需变更。尚未进行真实双端视频通话验证。


## 聊天中的通话记录

新增 chat_messages.kind（默认 text）及 metadata，消息接口返回 kind 和 call 结构。friend_calls 的数据库触发器在通话转为 ended 时，事务内写入双方共享的一条 call 消息，包含语音/视频、结束原因、接通状态和时长；用确定性消息 ID 防止挂断重试、重复更新或重启生成重复记录。拒绝、取消、未接听、失联、好友关系变化均被记录。正常时长从接听到挂断计算；失联时使用双方最后续租时间的较早者，避免把离线检测等待计入通话时长。

启动迁移幂等补录已有 ended 通话，记录仍带原结束时间；补录消息使用新的聊天游标，因此已有会话会在历史尾部收到这些记录。未来通话按正常结束顺序进入消息流。记录使用现有分页、最近会话预览、未读及已读机制。客户端与移动端增加通话类型标题和状态/时长展示，重开聊天仍可查看。

51 项通话集成检查通过，包括双端相同记录、65 秒时长、各结束原因一条记录、重试与重启不重复、旧版历史补录；86 项原私聊集成检查通过。移动端 social_screen.dart 分析无问题，桌面语法和隔离通话界面检查通过。本次通话记录变更尚未部署或覆盖安装。

## 通话界面与交互调整

移动端发起或接听后进入独立深色通话页，头像/视频、名称、时长及圆形媒体操作统一布局，挂断独立红色按钮。顶部全局横幅仅用于未展开的来电，正在通话时收起后显示底部紧凑“返回通话”入口，展开时完全隐藏全局入口，避免原有大横幅压住页面。重复点击不叠加通话路由，通话结束自动返回聊天；返回/收起保持媒体，不等于挂断。页面支持小屏滚动。

展开通话页时关闭安卓重复原生浮窗，收起后再显示；点击视频通话的收起按钮可申请浮窗权限。已有浮窗权限时应用进入后台仍可显示视频，回到前台根据页面是否展开决定浮窗显示。系统返回手势不会强制弹出权限设置，没有权限仍保留应用内返回通话入口。真实设备后台表现待复验。

桌面通话面板统一深色卡片，移至右下角，提供收起/返回按钮及通话计时，折叠后隐藏视频和媒体控件但保持通话。没有新增关闭按钮。模拟界面预览 friend-call-expanded.png 与 friend-call-collapsed.png 使用模拟信令/图像，非真实通话截图。

移动端七项相关测试通过，覆盖展开不叠加顶部横幅、收起入口位置、返回通话、结束返回聊天和既有 API/信令行为；代码分析无问题。桌面隔离界面检查确认折叠隐藏画面/控件且不结束媒体。当前界面调整与上一项通话记录变更均尚未部署或覆盖安装。
