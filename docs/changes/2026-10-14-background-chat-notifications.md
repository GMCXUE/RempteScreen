# 后台聊天系统通知

安卓后台收到聊天消息后使用系统 MessagingStyle 通知卡片：显示发送人、头像、时间及消息摘要，同一好友保留最近五条消息，多位好友使用应用通知分组和静音汇总。点击通知进入对应聊天；查看聊天或手动清除通知时仅更新本设备的通知游标，不将清除当作服务器已读。

修复后台通知因其它设备把服务器未读数降为 0 而在下一次轮询被撤销的问题。通知保留到本机查看或手动清除，好友被删除、拉黑或免打扰时清理。聊天消息与通话记录使用不同序列判断，消息后马上产生通话记录也不会遮掉聊天通知。原生服务取来电失败时仍继续同步聊天提醒。

移动和桌面同时新增“通知显示消息内容”，默认开启。安卓开启时声明公开锁屏内容，关闭后隐藏发送人、头像和正文并提供匿名公开摘要。开关关闭时撤销旧的含正文通知。桌面关闭时同样只发匿名摘要；macOS 按会话线程分组，使用同一记录标识替换同一会话提醒。Windows 提交稳定通知 ID，但当前 Tauri 通知后端无法撤销已显示的通知，这是桌面平台的现有限制；本次仅发布 macOS 和 Android。系统仍掌握锁屏、横幅、静音和通知样式，尊重用户已设置的通知权限。

服务器在现有账号状态中附加每个好友最近五条入站消息摘要和初始已读游标，单条最多 300 个字符，只来自当前账号与该好友的可见聊天，排除通话、撤回及已清空历史。复用原来的七天暂存机制，不增加内容副本或数据库表。通知正文仅交给系统通知中心；本地持久化的新增游标不包含聊天正文。

后台服务仍使用四秒轮询，没有新增厂商离线推送。系统强制停止进程后需要重新打开应用。Android 24–27 使用旧版 MessagingStyle 构造方法，28+ 使用 Person，旧安装包继续兼容服务器的新字段。

验证：服务端好友聊天检查 136 项、本地投递检查 29 项，覆盖账号隔离、五条上限、消息与通话分离、清空及撤回边界；安卓策略 9 项及原生编译；桌面通知策略 6 项及原生构建；移动端相关 Dart 文件静态检查。当前没有连接的 Android 手机，未验证锁屏实际外观或真机后台到达率。

发行：macOS 0.2.14、Android 0.2.20，构建号 2026101401，使用完整安装包。

参考：[Android 通知样式与锁屏显示](https://developer.android.com/develop/ui/views/notifications)、[MessagingStyle](https://developer.android.com/reference/android/app/Notification.MessagingStyle)。
