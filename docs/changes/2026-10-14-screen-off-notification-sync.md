# Android 锁屏同步与后台状态通知

用户实测 Android 0.2.27 在锁屏、熄屏时未收到消息。该版本的原生通知样式已经在正式 APK 的四条真实后台消息上验证：主通知列表、独立头像、名称旁系统时间、合并摘要及展开正文均正常，但不能据此宣布锁屏同步通过。后续真机复测期间手机在视频通话，锁定状态发生变化，该次数据不作为验收结果。用户选择自行完成最终锁屏验证。

代码存在两项缺失：后台轮询使用原生 Thread，但前台服务身份只保障生命周期，不会自动防止 CPU 在熄屏后休眠；消息分流及横幅确认仅依据 Activity 的 resumed 标记，未检查屏幕和 Keyguard。后者在“Activity 仍 resumed、设备已锁定/屏幕已熄灭”的框架回归场景中会把新消息判为当前聊天已看过或等待应用内卡片，不能提交系统通知。

本次补上真实可见条件：Activity resumed、屏幕可交互且未被 Keyguard 锁定。轮询、头像、当前聊天清除、横幅显示确认、原生聊天页面可见回调和来电弹出都使用此条件。锁屏或熄屏的新消息走系统通知，不消耗成已查看内容。

新增正常 WAKE_LOCK 权限及熄屏同步保护：屏幕关闭广播立即取得 PARTIAL_WAKE_LOCK；仍在运行且已登录的原生消息轮询每次请求/轮询续期，单次最长六十秒。屏幕亮起、退出账号、服务销毁或当前工作线程退出时释放；没有续期的异常线程不会无限保持 CPU。亮屏正常使用时不持有该保护。熄屏持续同步会增加待机耗电，系统强制终止、厂商限制以及 Doze 的网络政策仍由系统控制，需要最终真机验证；后续可接厂商推送以降低这项持续同步成本。

原来的“消息后台服务”和“设备待命”两条前台服务通知，改用相同通知 ID 和一个独立的最低优先级“后台运行状态”分类，不响铃、无振动、无角标、不在锁屏展示，支持系统延迟显示。Android 管理器会保留另一项仍在运行的前台服务所共享的通知；停止其中一项不会取消另一项的前台身份。移除旧分类和旧待命通知 ID。

Android 要求前台服务提交通知，应用不能在所有系统上默认完全隐藏它。新增“消息与来电提醒 → 系统通知与后台设置 → 后台状态通知设置”，直接打开这个分类，用户可单独关闭它；聊天、来电、好友和设备连接请求各自的分类不受影响。系统的运行中应用入口继续由 Android 管理。桌面没有这两项 Android 前台服务常驻提示；名称旁时间和消息/来电策略保留，差异来自平台运行机制。本次仅准备 Android 0.2.28 / 2026101409 完整安装包，无服务器协议、数据迁移或热更新。

`dumpsys activity service com.remotescreen.remotescreen/.MessagingService` 可读取运行状态、工作线程、屏幕/锁定状态、同步保护及最近轮询时间，便于在不打开应用的情况下定位后续失败；不输出凭据、用户/好友 ID 或消息内容。

## 验证与交付

Android 框架回归三十七项通过，包括熄屏仍 resumed 的当前聊天、亮屏锁定的横幅确认、原生分组/头像/系统时间、通知权限、已读清除、六十秒到期/续期/亮屏释放及合并状态分类不影响聊天和来电分类。Flutter 消息卡片和聊天视口十一项通过，四个相关 Dart 文件静态分析无问题。
