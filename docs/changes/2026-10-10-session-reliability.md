# 双端连接与文件传输修整

本次范围：Rust/Tauri 桌面端、Flutter 移动端、目录服务。保留移动端首页、投屏、我的设备、我的四个底部导航；文件传输有独立入口。

## 已修改

- 手机登录、设备注册、连接复用同一个 ApiService；双端配置统一为现有 Rust 服务地址。
- 连接请求使用明确的 `purpose: screen | files`，不再根据设备名称猜测操作。省略 purpose 的旧请求仍为 screen。
- 注册响应增加 `fileToken`。设备在 `files-{deviceId}` 房间保持数据接收连接，身份为 `file-host-{deviceId}`。文件令牌仅允许发数据，禁止发布/订阅媒体。
- 文件连接不再占用观看连接；停止投屏不会主动断开文件连接。双端均可从文件页面向另一端发送文件。
- 文件传输流程为 `meta → ready → chunks → end → saved`；只有收到目标参与者的 saved 回执才显示发送完成。发送数据与等待回执均有 30 秒超时；接收 60 秒无数据清理临时文件。
- 桌面接收文件先写入隐藏临时文件，再以不覆盖同名文件的方式发布完整文件；移动端保存到下载目录后才回执。
- 双端提供取消发送和本次运行的传输记录；失败后重新选择文件重试。尚不支持断点续传。
- 投屏声音与通话声音分开控制；观看端摄像头小窗绑定目标设备。桌面通话开关串行执行，断开后清理采集器；手机渲染器用代数避免旧异步初始化覆盖当前画面。
- 请求取消后检查迟到的批准结果；手机修复自有设备免确认分支、重复请求列表及无画面仍显示直播的问题。
- 双端文件接收连接在网络断开后每 3 秒自动重连；移动端用连接代数丢弃重复注册产生的旧连接。

## 更新顺序

1. 更新目录服务的 handlers.mjs、requests.mjs、token.mjs（无数据库迁移）。
2. 同时更新 macOS 与 Android 客户端，重新登录或重新注册设备以取得 fileToken。
3. 再进行双机联调。旧服务端没有 fileToken 时，新客户端会提示升级，不会退回到开启投屏来传文件。

2026-10-10 已更新 `121.43.102.154` 上的目录服务并覆盖安装两端客户端。服务端旧源码备份在 `/opt/remotescreen/.deploy-backups/20261010-1635-file-sessions`；数据库、LiveKit 和 Caddy 未重启。文件接收依赖客户端进程存活，Android 被系统杀死后无法仅靠通知服务接收文件。
