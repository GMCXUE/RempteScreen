# 头像和资料保存后的提示错误

桌面头像、资料模块调用 `toast()`，但该函数只定义在 social.js 的立即执行函数内部。服务端已成功保存后，执行成功提示触发 ReferenceError，使保存弹窗留在原处，并把前端提示异常显示为保存错误。读取资料失败的错误提示也受影响。

新增 feedback.js 提供 `window.showAppToast`，在所有功能脚本之前加载。头像和资料保存确认后关闭弹窗，再显示成功提示；读取失败也通过同一提示接口反馈。消息、文件接收、投屏结束、好友通话通知统一使用共享的提示计时器，替换内容时清除旧定时器和点击行为，退出账号时清理提示，保留原有提示文字和持续时间。

Flutter 同步整理账号操作的成功提示。个人资料页更换头像后立即显示“头像已更新”，不依赖后续资料刷新是否成功；首页/我的使用相同反馈方法，重复操作替换已有提示。无需修改服务端或数据库，已保存头像不需要重新上传。

之前的隔离浏览器检查人为注入了全局 toast 空函数，掩盖了桌面脚本作用域错误。本次新增仓库内的真实提示回归检查，不注入 toast，按 index.html 中的加载顺序加载真实的反馈、头像、资料、好友脚本，仅模拟原生桥和接口数据。

验证：

- 桌面 `apps/desktop-rs/app/test/account-profile-ui.cjs` 通过：默认头像与自定义头像保存成功后提示/关闭、失败保留选择及重试、资料保存、资料读取失败、提示计时器替换、退出清理，确认没有全局 toast 依赖及页面异常。
- 6 个相关桌面脚本语法检查通过。
- 移动端头像和资料的 6 个针对性测试通过，含后续资料刷新失败时仍提示头像已保存；新增提示文件及改动文件静态分析无问题。
