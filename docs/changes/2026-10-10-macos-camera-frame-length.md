# macOS 摄像头首帧解析修复

摄像头辅助进程已获得权限并启动，但桌面端一直显示摄像头关闭，投屏方也收不到视频。Rust NV12 帧长度校验把 `width * ceil(height / 2)` 写成了 `width * (height + 1) / 2`，造成 640×480 帧预期值为 461120 字节，而 Swift 采集器实际输出 460800 字节。首帧被判为无效，摄像头轨道尚未发布便退出。

修正 UV 行数取整位置，并对尺寸、长度及溢出进行校验。启动失败时保留真正的帧读取错误，不再用 stderr 中的 `camera-capture: started` 覆盖错误；成功发布后记录轨道 ID 和分辨率，方便确认采集与发布分别完成。

增加合成 NV12 协议回归测试，覆盖真实 VGA 长度、连续帧边界、错误长度、截断数据和非法尺寸。此修复针对 macOS 原生摄像头辅助进程协议；安卓使用 WebRTC 原生采集，不使用此协议，现有双端摄像头和视频悬浮窗功能保持一致。

验证：2 项摄像头协议回归测试通过，macOS release 应用打包成功。未自动开启真实摄像头或进行实机通话测试。
