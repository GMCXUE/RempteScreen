# 单聊设置与聊天历史

按用户参考图实现，群聊及拉人建群留到后续。主桌面端右上角三个点打开聊天栏内的右侧侧栏；好友头像可打开资料，保留备注、拉黑和删除入口。移动端聊天右上角三个点进入独立“聊天信息”页面，仅提供查找聊天记录、消息免打扰、置顶聊天、清空聊天记录四项；首页底部导航不变。

桌面查找打开原生独立窗口（760 × 720，可调整大小）；移动端进入独立历史页面。搜索服务端全部可见历史，不受聊天中当前加载的 50 条消息限制。支持全部、文字、图片、链接、通话，以及单日日期筛选，可组合关键词并继续加载更早记录。图片可查看原图。定位按钮返回主聊天，读取目标周围上下文并高亮目标；移动端将目标放在可见消息区开头，之前的内容仍可继续向前加载，避免不同高度的图片导致定位偏移。

当前单聊没有文件、视频附件、音乐、小程序或视频号消息，历史界面不展示不可用类别。现有文件传输仍在独立文件传输功能中。

## 行为与协议

- `POST /v1/social/history`：Bearer 登录与双向好友授权。请求 peerId、query（最多 200 字符）、kind、before；可传本地日历换算后的 from/to 毫秒边界，from 包含、to 不包含。每页最多 50 条，返回 messages（按数字 seq 倒序）和 hasMore。关键词为字面匹配，百分号、下划线和反斜线不作为通配符。搜索不返回已撤回消息。
- `POST /v1/social/message-context`：peerId、messageId；只允许定位本会话且未被当前账号清空的消息。返回前后上下文、hasMore/hasNewer、syncCursor、clearedThrough。客户端复用现有消息/撤回轮询。
- `POST /v1/social/profile` 的 action=pin、pinned=boolean：仅修改当前账号与该好友的置顶，跨登录设备持久化；服务端置顶优先排序，空会话置顶后仍在最近会话出现。
- `POST /v1/social/clear-history`：事务锁与发送/撤回共用好友对的序列化机制，记录当前会话最大 seq 为本账号的可见边界。清空只影响自己的历史，并同步到本账号其他设备，不删除对方的记录。确认文案明确同步范围和不可恢复。已清空图片的原图读取也被拒绝。
- `messages` 增加 clearedThrough 字符串；两端轮询会清除该边界以内的旧消息、已打开的旧图片/文字选择界面，避免缓存回流。未读、会话预览和历史查询使用相同边界。草稿及通话不受影响。
- 消息免打扰沿用双端现有的本设备通知设置：消息保留未读，来电静音。没有改变原本的通知协议或范围。

数据库通过幂等迁移在 friend_profiles 增加 pinned 与 cleared_seq，已有记录默认 false/0，不回填或删改历史消息。清空是账号侧可见性操作，底层消息仍为对方保留。

桌面历史窗口不持有登录凭据：原生桥保存当前账号与会话快照，验证窗口和当前账号的令牌仍相同，只开放历史/头像/原图查询，并强制使用快照 peerId。切换账号或退出关闭窗口；定位事件包含账号和会话标识，主窗口再次核对后处理。关键词和远端消息均以 textContent 渲染，避免历史搜索引入 HTML 注入。
